# Bootstrap deletion readiness: execution plan for GPT Luna

## Goal and boundary

Make it possible to remove `/home/luke/bootstrap` without losing or breaking the **installed** Kilo context (global agents, commands, rules, skills, MCP configuration) or host tooling that is intended to remain useful. Do not delete the checkout as part of this work. Repository-local `AGENTS.md`, `.kilo/`, `.kilocode/`, and provisioning/reinstallation sources will necessarily disappear with the checkout; do not claim they survive unless deliberately migrated. Do not commit or push without a separate explicit request.

The worktree was already dirty at planning time, including `AGENTS.md`, `README.md`, `example.bootstrap.conf.yml`, `init.d/lib/conf.sh`, both access scripts, and access-script tests. Inspect the current diff before editing those files; preserve concurrent work.

## Implementation

1. **Preserve the Air template outside the checkout.** Choose one stable deployed path, preferably alongside the installed Air skill (for example `~/.kilo/skills/air/assets/air.toml.template`), and make `30-scripts/run.sh` install the existing canonical template there as an ordinary file. Alternatively put the template in the Air skill source tree and let the existing skill sync deploy it; keep one authoritative source rather than divergent copies. Update both occurrences in the *source* Air skill to use the deployed path. Ensure a rerun updates a changed template and does not delete user-added skills. Verify the installed copy and template match the source after provisioning.

2. **Make Caddy references durable.** Preserve the operational guide at a stable path outside bootstrap (prefer a location associated with the existing `~/infra/caddy` installation); deploy/copy it through the Caddy step or another appropriate existing user-tier mechanism. Update the *source* central-Caddy skill to name the surviving location. The `_plans/central-caddy.md` design document is historical: either archive a copy outside bootstrap if it is genuinely needed for ongoing operation, or remove its link from the live skill and explicitly record that it will be lost. Do not turn a design plan into an operational prerequisite without need. Verify the chosen reference files exist in the live installation.

3. **Resolve checkout-dependent access commands deliberately.** Inventory each installed `github-access` subcommand and `bootstrap-access` workflow against `BOOTSTRAP_ROOT`, `init.d/lib/conf.sh`, `user/init.sh`, and `.env` using the *current* dirty worktree versions. Recommended minimal outcome: treat `bootstrap-access` and setup/reprovision subcommands as bootstrap-only, document their retirement when the checkout is removed, and preserve any operational subcommands that can work from installed credentials alone (e.g. `github-access clear`) with explicit checks that do not require the checkout. If the operator actually needs post-deletion setup/reprovision, move the required configuration and logic into a supported persistent host location instead; do not copy the whole repo or guess defaults for capability/credential policy. Update help, errors, and applicable tests to state the supported contract. Do not alter token storage or expose secret values.

4. **Audit all live inputs and deploy the changes.** Search `~/.config/kilo`, `~/.kilo/skills`, other active agent context roots, and retained `~/scripts`/`~/.local/bin` runners for literal bootstrap references, symlinks into bootstrap, and dynamic checkout resolution. Classify each as executable dependency, documentation link, provenance, or intentionally retired provisioning. Check any live-versus-source drift first: `37-kilo-settings/run.sh` copies `kilo.json`/`kilo.jsonc` only when absent and otherwise warns, so do not assume rerunning it refreshes config. Apply changes to source files, run only the relevant user-tier deploy steps if safe, and verify live copies directly; preserve local customizations.

5. **Validate deletion readiness without deleting or renaming the checkout.** Test the Air skill's documented copy operation using the deployed template in a disposable workspace-local `.tmp/` directory. Validate Caddy references and Kilo rules/MCP config in their live locations. Test supported access-script commands with a deliberately nonexistent `BOOTSTRAP_ROOT` where safe, using mocks for destructive/remote actions; never run interactive credential setup, token clearing, or a provisioning sweep just to test readiness. Run available shellcheck/tests for touched scripts and review `git diff`. Re-scan active context and host scripts for `~/bootstrap`, `/home/luke/bootstrap`, `BOOTSTRAP_ROOT`, and symlinks to the checkout; every remaining match must be documented as harmless provenance or an explicitly retired action. Report residual limits: deletion removes bootstrap-specific provisioning and repo-local instructions by design, and this audit is not a guarantee about arbitrary applications outside the inspected host paths.

## Acceptance criteria

- Installed Kilo agents, commands, rules, skills, and MCP configuration remain ordinary files/independent paths, with no required checkout target.
- Following the live Air skill to create a project `.air.toml` succeeds without bootstrap.
- Every operational reference in the live Caddy skill resolves outside bootstrap, or is removed as intentionally historical.
- Each retained access command has an honest documented post-deletion contract; commands advertised as working without bootstrap have tests demonstrating that property. Bootstrap-only commands fail clearly rather than appearing to work.
- A final evidence table lists remaining bootstrap references, their classification, and any deliberately lost repository-local context. No actual deletion, commit, or push occurs under this plan.
